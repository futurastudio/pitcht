## Resulting behavior

- The [atomic public cutover](ATOMIC-CUTOVER.md) combines locked completion backfill, immutable billing/usage contracts, explicit capped legacy processing admission, and client ACL contraction. It fails if RLS would filter baseline reads. No Auth or Storage platform changes are required. Post-commit recovery is forward-only.
- Recording saves keep a stable capture UUID and Storage path. Upload checkpoints and owned metadata reconciliation handle lost responses without creating another object/row or overwriting media. AI processing starts only after the recording row is confirmed. Unsaved captures can be downloaded or explicitly discarded locally without advancing the question.
- Transcription/feedback require an authenticated owned recording ID. Legacy clients receive actionable upgrade guidance. Saved-video audio recovery compresses in the browser, supports cancellation/progress, and keeps original media intact. It is bounded to ten minutes/four MiB and runs in real time.
- Switching answers discards stale video, feedback and transcription results. Actual MIME types are preserved, including MP4. LocalStorage contains recovery metadata, never serialized Blobs presented as recoverable media.
- Signup notifications require a confirmed recent Auth account, derive identity/recipient from Auth, use the durable budget, and retry with stable provider idempotency. Duplicate waitlist enrollment does not resend. Both paths remain best effort; no complete public anti-bot defense is claimed.
- Purchase analytics retries retain their first durable purchase-record timestamp as well as UUID/insertion identity. Invalid/missing timestamps remain pending. This is not necessarily the original Stripe completion time, and actual external deduplication is not yet proved.
