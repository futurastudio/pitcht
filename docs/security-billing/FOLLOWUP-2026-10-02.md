## Changes

- **History recovery:** saved session details expose “Recover this answer” when feedback is absent. The link contains both saved IDs; analysis hydration verifies the owner and selects that exact recording. Both detail and analysis reject another owner's session. Stale detail/video requests cannot replace the current selection.
- **Feedback safety:** a shared normalizer checks diagnosis shape, known pattern, exact transcript evidence, bounded drill text/duration, and timestamps within the recording. Invalid diagnosis is omitted; canonical labels replace model labels. Communication fields and improvement examples/priorities are normalized before new persistence, API cache delivery and rendering. The callout separately validates legacy data. Core scores, including zero, remain intact. Prompts/models/rubrics are unchanged.
- **Shared-browser privacy:** versioned recovery records carry the authenticated owner and use per-owner keys. Unowned legacy metadata is discarded; saved server recordings remain reachable through History. Account changes remove other owners' browser metadata, reset PostHog identity and remount private React state. Late entitlement results carry an identity generation check. Unconfirmed signup does not install a user as authenticated. Explicit sign-out/account changes and deletion are blocked while captures need save/download/discard; forced Auth transitions clear private state immediately. Public content still server-renders while Auth resolves. Media bytes remain memory-only.
- **Deletion failures:** inventory uses `video_url`, pages all canonical subscription rows and recursively pages the owner's Storage prefix, including orphan uploads. All Stripe subscription/customer/metadata ownership checks finish before cancellation begins. Confirmed terminal subscriptions are skipped; cancellation explicitly disables invoice-now and proration. Any query, cancellation, Storage, session or Auth error prevents a success response. Billing bindings remain until final Auth deletion; no manual binding deletion or broad Stripe customer deletion occurs. Partial cleanup is retryable and the UI explains unconfirmed completion. Payment records retained at Stripe are no longer promised deleted.
